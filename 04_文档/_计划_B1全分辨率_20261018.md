# B1 全分辨率 640×480 改造方案（待实施）

> 日期：2026-10-18 ｜ 目标：把帧缓存从 320×240 恢复成 **640×480 全分辨率**（去掉写侧 2×2 降采样、读侧 2× 最近邻）
> 前提：当前 30fps + frame_end EOF 对齐版已上板稳定（P0 关闭）。任何改动不得破坏它；`_bitbk/camera_hdmi_20261018_1743_framend_eof.bit` 是回退点。

## 1. 为什么要做

- 赛题基础要求第 1 条：采集 ≥640×480、无丢帧无错位；团队自己的组会材料把“分辨率”列为**唯一未达标的基础项**。
- 现在 DDR3 已通，片内 RAM10 只用 148/256，带宽余量 300×，全分辨率在资源上完全可行。
- 全分辨率后边缘图细节明显更好，演示视频更有说服力。

## 2. 现状与全分辨率的差异

| 项 | 现在（320×240） | 全分辨率（640×480） |
|---|---|---|
| `STORE_W/H` | 320/240 | 640/480 |
| 写侧地址 | `srow=row_d1>>1`、`scol=(pcol-2)>>1`，只写偶行偶列 | `srow=row_d1`、`scol=pcol-2`，每像素都写 |
| 写侧字节/帧 | 75,922 | **307,200**（= 640×480，且 307200/1024=300 整除 ✓） |
| `C_RD_END_ADDR` | 76800 | **307200** |
| `rd_col` 宽度 | 9 bit（0..319） | **10 bit（0..639）** |
| 读侧取数 | 每 2 个显示像素取 1 字节 + 垂直 2× 复用 lbuf | **每个显示像素取 1 字节**（无 2× 放大） |
| `lbuf` | 320×8 | 640×8（5120 bit，仍 1 块 RAM10） |
| 时域降噪 `u_hist` | 76,800×8 = 76 块 RAM10 | 307,200×8 = **300 块 RAM10 —— 装不下，必须关掉** |
| 边缘历史 `u_hist_edge` | 76,800×1 = 10 块 | 307,200×1 = **40 块（可保留）** |
| DDR 带宽 | 写 1.14 MB/s / 读 4.56 MB/s @60Hz | 写 4.6 MB/s / 读 18.4 MB/s @60Hz —— 仍可忽略 |

> 结论：全分辨率的真正代价不是 DDR，而是**必须放弃 `u_hist` 时域 IIR**（BRAM 不够）。
> 交接手册也说过：“失去时域混合降噪。可接受 —— 线 B 的 3×3 中值滤波才是主要降噪手段。”

## 3. 具体改动清单（按文件）

### 3.1 `camera_hdmi.v`

1. 参数：`STORE_W=640, STORE_H=480`。
2. 写侧（8 节）：
   - `srow = row_d1`（不再 >>1），`scol = pcol - 2`（不再 >>1）；
   - `ds_par` 删除（每像素都写）；
   - `fb_addr_c = row_d1*640 + (pcol-2)`，用移位加法：`{row_d1,9'b0} + {row_d1,7'b0} + scol`（640 = 512+128）；
   - `fb_ok` 不再与 `ds_par` 相与；
   - 位宽核对：最大 479*640+638 = 307,198 < 2^19（AW 需从 17 改成 19）。
3. **关闭时域降噪**：`blend_raw = 1'b0`（或 `generate if` 不例化 `u_hist`）；同时不再例化 `u_hist`，省 76 块 RAM10。
   - `u_hist_edge` 可保留（全分辨率 40 块），用 `srow*640+scol` 地址。
4. 读侧（9a/8b）：
   - `drow = dy_d`（不再 >>1），`dcol = dx`（不再 >>1；640 列）；
   - 删除 318 镜像（全分辨率下 dcol 0..639，无需镜像）；
   - 删除垂直 2× 复用（`frow_ok` 条件改为每行都取），`fb_fetch = de_disp & (dcol != dcol_d)`；
   - `rd_col` 位宽 10 bit。
5. `ddr_frame_buffer` 例化：`STORE_W/STORE_H`、`AW(19)`、`C_RD_END_ADDR(307200)`。
6. `gate` 相关：`C_BURST_LEN=64`（1024 B）仍然整除 307,200（300 笔）✓。
7. UART 缩略图：`ssram` 写侧的 10×10 盒式平均逻辑基于“显示 2× 放大”，全分辨率下要重算（10 显示像素 = 10 源像素，不再是 5 源像素）；不改会偏亮/混叠。**B1 里一起改**。
8. 自检 `SELFTEST` 的期望斜坡计数器：全分辨率下 `srow*640+scol`，计数器/地址判断仍可用，但桶号范围变大；保持 SELFTEST=0 即可。

### 3.2 `ddr_frame_buffer.v`

1. `STORE_W=640, STORE_H=480`（默认参数）；
2. `AW=19`；
3. `rd_col` 端口 `[9:0]`；
4. `lbuf` 深度 `STORE_W`（640）；
5. `C_RD_END_ADDR = STORE_W*STORE_H = 307200`（默认值）；
6. `wframe_vsync` 仍用 `wr_frame_end`（P0 修复，保留！）；
7. `rd_fetch`/`rdata` 逻辑不变，但取数变成每像素一次（无 2× 复用）。

### 3.3 `ov5640_cfg_rom.v` / 传感器

- 分辨率不变（还是 640×480 采集），ROM 不用改（除了 P1 固定曝光）。
- 30fps（VTS=1688）保持不变；全分辨率下 DVP 数据率不变（采集本来就是 640×480）。

## 4. 资源预算（估算）

| 项 | 变化 | 结果 |
|---|---|---|
| `u_hist` | -76 块 | 148 → 72 |
| `u_hist_edge` | 10 → 40 块 | +30 |
| `lbuf` | 320→640×8，仍 1 块 | 0 |
| 写地址/读地址逻辑 | +少量 LUT/FF | 可忽略 |
| **合计 RAM10** | | **约 102 / 256** |

结论：资源很宽松，甚至可以保留 `u_hist_edge`；若后面还要加中值滤波（+2 行缓存 = 2 块），也没问题。

## 5. 风险与验证

| 风险 | 说明 | 缓解 |
|---|---|---|
| 写地址/位宽算错 | 全分辨率地址 19 bit，`srow*640+scol` 用移位加法 | iVerilog 小 tb 验地址序列；上板看是否有斜纹/错行 |
| 读侧取数节拍 | 每像素取一次，`dcol != dcol_d` 在 640 列下每列都变 | 用 UART 1:1 窗口（THUMB_RAW=1）验相邻像素相关 >0.9 |
| 帧缓存对齐 | 全分辨率 307,200 = 300×1024，burst 对齐 ✓ | 但 EOF/帧边界要重验（frame_end 修复保留） |
| 缩略图 10×10 盒式平均 | 2× 放大没了，块大小要重算 | 一起改，用串口图确认亮度/无混叠 |
| 时域降噪丢失 | 噪点/闪烁可能变多 | 中值滤波（同学）是主要降噪；或先把 `u_hist_edge` 保留 |
| 时序 | 地址位宽变大、逻辑变多 | 构建后检查 slack > 0、RAM10、违例 0 |

**验收标准**：
1. 构建 4 步 exit=0、0 违例、RAM10 ≤ 160；
2. 状态字 FF、相机 30.00fps、显示 60.00Hz、hold=2；
3. UART 1:1 窗口：横/纵相邻 Pearson > 0.9；
4. HDMI 全屏 640×480 无黑边、无错行、无左右抖动；
5. 与 320×240 版对比：边缘细节明显增加，帧率/延迟不变。

## 6. 实施顺序建议

1. 先改 `ddr_frame_buffer.v`（参数 + rd_col 位宽 + lbuf），单独构建确认不报错；
2. 再改 `camera_hdmi.v` 写侧（地址/去降采样/关 u_hist）；
3. 再改读侧（drow/dcol/去 2×）；
4. 最后改缩略图盒式平均；
5. 每步构建 + 备份，最后上板一次验收。

> 预计 1 天（含 2–3 次上板迭代）。
