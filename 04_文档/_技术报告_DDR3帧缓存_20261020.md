## 1. 系统概述

### 1.1 数据流

```
OV5640 (DVP 8bit, RGB565, 640×480)
   → DVP 采集（cmos_pclk 域）
   → 灰度化 Y8 = (77R + 150G + 29B) >> 8
   → 3×3 Sobel 梯度 |Gx|+|Gy|
   → 双阈值迟滞（LO=48 / HI=64）+ 时域两帧一致性
   → [基础版] 2×2 降采样 → 320×240 RGB332/灰度
     [高阶版] 逐像素 → 640×480 RGB332 / 红色边缘
   → DDR3 帧缓存（4 块 × 4MB，顺序写 / 顺序读）
   → 行缓冲 → [基础版] 2× 最近邻放大 / [高阶版] 1:1
   → TMDS → HDMI 640×480@60Hz
```

## 2. DDR3 帧缓存架构

### 2.1 为什么用 DDR3

原方案用片内 BRAM 做 320×240@8bpp 双缓存：2 × 76,800 × 8bit = 150 块 RAM10，占满 256 块的 59%，任何新功能都加不进去；若做 640×480 双缓存，每像素只有 3.41 bit，只能 3bpp + 抖动，画质明显下降。板载 DDR3 4Gbit×16 容量/带宽都足够，**把帧缓存整体搬到 DDR3**，片内只留 1 行行缓冲（1 块 RAM10）。

### 2.2 结构

- **DDR 控制器**：官方 `DdrCtrl`（含 4 个 4MB buffer）、`W0_FIFO_8`（写 FIFO）、`R0_FIFO_8`（读 FIFO）、`AXI4_AWARMux`、`axi4_ctrl`（官方原样，未改）。
- **帧流**：摄像头像素 → 写 FIFO → `C_BURST_LEN × 16B = 1024B` 一组写 burst；显示侧按顺序读回，**不做随机寻址**。
- **4 块 buffer**：写指针按帧推进，4 块轮转，写读不撞块 → 无撕裂。
- **帧边界**：每帧写满/摄像头帧边界触发 EOF，写 FIFO flush 后切换到下一块；读侧在显示帧起始切换到已完成的块。
- **校准**：上电自动校准（`cal_done`/`cal_pass`），失败自动重试；状态字 bit2/bit3 上报。

### 2.3 关键参数

- `C_ADDR_INC = 64 × 16 = 1024 B`
- 基础版：一帧 75,922 B（76 个 burst 内），`C_RD_END_ADDR = 76,800`；
- 高阶版：一帧 **303,688 B**，`C_RD_END_ADDR = 307,200`（读多读几拍无害，显示侧只消费 303,688 B）。
- 带宽：写 9.1 MB/s、读 18.2 MB/s（30fps/60Hz），DDR 余量 100× 以上。

### 2.4 第 42 轮修复（保留）

`waddr_d` 只在写使能 `we` 有效时更新，避免空拍地址跳变造成写指针错位。

## 3. 问题与修复

### 3.1 P0：HDMI 画面抽动（已关闭）

**现象**：整幅图像逐帧左右位移，每帧基本完整。

**根因（两个叠加）**：

1. **帧率非整数比**：实测相机 **51.46 fps**（`cam_period=1,865,664` 拍），显示 60.00Hz，51.46:60 非整数 → 帧节奏不齐，画面周期性"抽"。
   - 修复：OV5640 `VTS 984 → 1688`（`0x380e=0x06, 0x380f=0x98`），相机 **30.00 fps**（`cam_period=3,200,448`），与 60Hz 严格 **2:1（hold=2）**。
2. **写侧 EOF 用地址回绕**：`waddr` 回绕时触发 EOF，但跨时钟域/流水延迟会让新帧前 0~N 字节 flush 进旧 buffer → 每帧水平偏移量随机。
   - 修复：EOF 改由**摄像头帧边界 `frame_end`** 产生（`ddr_frame_buffer` 新增 `wr_frame_end` 端口），在摄像头帧结束处收尾，新帧数据不会混入旧 buffer。

**验证**：状态字 FF、30.00fps/60Hz/hold=2、左右抖动消失（用户上板确认）。

### 3.2 B1：恢复 640×480 全分辨率（已完成）

**改动**：

| 位置 | 改动 |
|---|---|
| 参数 | `STORE_W/H = 640/480` |
| 写侧 | `srow = row_d1`、`scol = pcol-2`、去掉 2×2 门控 `ds_par`；地址 `srow*640 + scol`（19 位）；RGB332 从 2×2 四点平均改为**逐像素** |
| 读侧 | `drow = clamp(dy, 2, 477)`、`dcol = (dx<3)?0:(dx-2)`；每行 638 取数；行门限 2..477 |
| `ddr_frame_buffer` | 参数 640/480、`AW=19`、`rd_col` 10bit、`lbuf` 640 深 |
| 降噪 | 全分辨率 IIR（`u_hist`）需 300 块 RAM10，**generate 条件化关闭**；边缘时域历史 `u_hist_edge` 保留（38 块） |

**账本**：写 = 读 = 476 × 638 = **303,688 B/帧**；RAM10 148→**91**；时序 +0.026ns、0 违例。上板确认"明显更清晰"。

### 3.3 两套 bitstream

| | 基础版 | 高阶版 |
|---|---|---|
| 参数 | `SPLIT=1, EDGE_COLOR=0` | `SPLIT=0, EDGE_COLOR=1` |
| 画面 | 左半屏原始灰度 / 右半屏 Sobel 边缘 | 全屏 RGB332 彩色 + 纯红边缘 |
| 分辨率 | 320×240 + 2× | 640×480 |
| RAM10 | 83 | 91 |

> 曾尝试"全分辨率左右分屏"，但构建后 DDR 控制器内部 `core_clk → twd_clk` 路径出现 **-0.015 ns** 违例（官方 IP 内部路径，PnR 变化导致），为守住"时序 0 违例"未采用，基础版继续用 320×240 左右分屏。

### 3.4 分屏实现（基础版）

- 左半屏 `dx 0..319` 显示 `fb_rdata`（灰度），右半屏 `dx 320..639` 显示边缘缓存 `edge_q`；
- 两半走同一套取数（`dcol=dx>>1`、垂直 2×、行 1..238），DDR 流每帧 75,922 B 完整消费；
- 左右两半分别对应场景左半/右半，中央接缝连续、宽高比正确。

## 7. Canny 边缘检测（高阶挑战 #4，A 线）

- 模块：`canny_core.v`，参数 `GAUSS_EN` 选两版：
  - `GAUSS_EN=0`：简化版（Sobel 原始灰度 → 方向量化 → NMS → 双阈值+滞后）；
  - `GAUSS_EN=1`：严格版（3×3 高斯 1-2-1 → Sobel → 方向量化 → NMS → 双阈值+滞后）。
- 方向量化：`|Gx|`/`|Gy|` 比值 → 0/45/90/135°，**不做 atan/CORDIC**；
- NMS：3 行 mag/dir ring，比较沿方向的邻域；对角方向用“上斜两邻”近似；
- 双阈值 + 简单滞后（强 | 弱且左/上有强）；
- 延迟：1 行（NMS 需要上一行+当前行）；集成时写地址需延迟 1 行；
- 仿真（64×64 合成图，两版同时跑）：

| 测试图 | GAUSS_EN=0 | GAUSS_EN=1 |
|---|---|---|
| 8×8 棋盘格 | 763 | 651 |
| 填充黑圆 r=20 | 158 | 190 |
| 黑矩形 40×32 | 142 | 146 |

- 资源：raw 3 行 + gauss 3 行 + mag/dir 3 行（约 6–9 块 RAM10，视综合），320 分屏 bit 当前 RAM10 83/256，余量足够；
- 待办：集成到 320 分屏源码（`EDGE_SRC` + 1 行地址延迟 FIFO），构建两版 bit，上板对比后择优写入报告/演示。
- **集成构建（2026-10-22）**：
  - 简化版 `EDGE_SRC=1`：1,906,587 B、RAM10 84/256、min slack +0.026 ns、0 违例；
  - 严格版 `EDGE_SRC=2`：1,895,295 B、RAM10 87/256、min slack +0.026 ns、0 违例；
  - 集成方法：320 左右分屏 + 中值 + `canny_core` + 1 行地址延迟 FIFO；两版待上板对比。
