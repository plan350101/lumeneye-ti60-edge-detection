## 结论（当天已上板验证）

**P0 抽动已定位并修复，根因与交接文档的 R1「传感器只有 15fps」不同。**

实测（UART 帧头遥测，96MHz 拍）：
- 相机实际 **51.46 fps**（周期 1,865,664 拍 = 19.43ms），不是 15fps；
- 显示 **60.00 Hz**，帧周期 1,600,000 拍；
- 每个相机帧跨 1~2 个显示帧（hold=1/2）⇒ 51.46 : 60 是**非整数比**，运动必然一顿一顿。

抽动其实是**两个独立问题叠加**：

### 问题 1：相机 51.46fps ↔ 显示 60Hz 非整数比（时间节奏抖动）
- 现象：运动物体按 1,1,1,1,2… 的节奏跳动（约 8.5Hz）。
- 修法：把 OV5640 的 **VTS 从 984 改成 1688**（`ov5640_cfg_rom.v` rom[66]=0x380e06、rom[67]=0x380f98）。
- 结果：相机 **30.00 fps**，显示 60Hz，**hold=2（严格 2:1）**，帧节奏抖动消除。
- 说明：VTS=844（想提到 60fps）那一版**会 DDR 校准失败（cal_pass=0）**，已弃用；VTS=1688 稳定。
- 备注：`0x380F` 高字节也要同步改（1688=0x0698），不能只改低字节。

### 问题 2：整幅画面逐帧左右抖动（DDR 写侧帧边界对齐）
- 现象（用户描述）：每一帧图像都基本完整，但整幅图左右位移，连续抖动。
- 根因：`ddr_frame_buffer.v` 原来用**写地址回绕**产生写侧 EOF。回绕恰好发生在新帧第一个写字节那一拍；`wframe_vsync` 经 clk_sys 两级同步有 2–3 拍延迟，这段时间里新帧最前面的 0~N 个字节已进 W0_FIFO，EOF flush 把它们写进**旧 buffer 尾部**，于是新 buffer 从第 N 个字节开始 ⇒ 整幅图水平偏移 N 个存储像素，每帧 N 不同 ⇒ 左右抽动。
- 修法：改成用**摄像头帧边界 `frame_end`**（row 计数回绕，在新帧第一批写字节之前约 2 行 ≈ 40µs）产生写侧 EOF。flush 在新帧数据到来前完成，新 buffer 从字节 0 开始。
  - `ddr_frame_buffer.v` 新增端口 `wr_frame_end`，EOF 生成改用它；旧的 `w_addr_wrap` 逻辑保留但不参与 EOF。
  - `camera_hdmi.v` 例化处接 `.wr_frame_end(frame_end)`。
- 结果：上板确认**左右抖动消失/明显减轻**。
