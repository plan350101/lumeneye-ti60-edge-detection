# 3×3 中值滤波集成说明（预留接口 / 验证清单）

> 2026-10-20 · 给算法线同学 / 后续集成用
> 现状：顶层已预留 `parameter MEDIAN = 1'b0`（`camera_hdmi.v` 约 L229），**尚未实例化任何中值模块**；本文件只定义插入点、接口、时序对齐和验收标准，不改动现役 bit。

---

## 1. 插入位置（写侧灰度流水）

```
OV5640 RGB565
  → gray8 / gray_c（Y8，ACTR 拉伸后）
  → gd1 → gd2（两级对齐）
  → 3×3 tap 链（cur_t1/t2、r1_t1/t2、r2_t1/t2）
  → Sobel |Gx|+|Gy| → 迟滞(48/64) → 帧缓存
```

中值滤波应插在 **`gray_c` 之后、Sobel 3×3 窗口之前**（即 `camera_hdmi.v` 里 `gd1 <= gray_c;` 这一级之前），用 3×3 邻域中值替换中心像素，再送 Sobel。

- 参考代码：`camera_hdmi.v` 约 L727–L808（两级流水 + 3×3 tap 链），`gd1 <= gray_c`（约 L767）。
- 现有 3 条灰度行缓存 `u_gl0/1/2`（`line_buffer #(.WIDTH(IMG_W), .DW(8), .AW(10))`，约 L660–L680）已经提供"上一行/上上行"的读数据；中值模块**可以复用这 3 行缓存**（把 9 个抽头先做排序取中值，再算 Sobel），这样 **+0 块 RAM10**，只加约 300 LUT。若模块自带 2 行缓存，则 +2 块 RAM10。

---

## 2. 建议模块接口

```verilog
module median3x3 (
    input  wire        clk,        // cmos_pclk（约 48MHz）
    input  wire        de,         // cap_de（有效像素）
    input  wire [7:0]  din,        // gray_c
    output wire [7:0]  dout,       // 3×3 中值
    output wire        de_out      // 与 dout 对齐的有效标志
);
```

- 位宽 8bit，与灰度流水一致；纯组合/小流水，无乘法器。
- 若复用现有 3 行缓存：模块输入改为 9 个抽头（`h,e,g,i,...`），输出 `med`，插入在 Sobel 核计算之前；此时 **不需要额外的行缓存和 `de_out`**。
- 若自带行缓存：输出相对输入延迟 **2 行 + 1~2 像素**；顶层必须把 `cap_y` / `pcol` / `cap_de` 同步延迟同样的量（否则写地址列 `scol=pcol-2`、行 `srow=row_d1` 会偏 2 行，画面整体上下错位）。

## 3. 资源与时序

| 方案 | RAM10 增量 | LUT 增量 | 现役 headroom |
|---|---|---|---|
| 复用现有 3 行缓存（推荐） | **0** | 约 300 | 高阶 91→91 / 基础 83→83 |
| 自带 2 行缓存 | **+2** | 约 300 | 高阶 91→93 / 基础 83→85 |

- 两块 bit 的 RAM10 上限 256，余量充足；时序上中值网络是纯组合排序，挂在 `cmos_pclk`（48MHz）路径上，`clk_sys`/`tac_clk` 不受影响。
- 红线：**不要**把中值逻辑放进 `tac_clk`/`twd_clk` 域；不要改 FIFO 参数。

## 4. 集成步骤

1. 把 `median3x3.v` 放进工程目录，加入 Efinity 文件列表（`camera_hdmi.xml`）；
2. 在 `camera_hdmi.v` 写侧灰度流水处实例化（复用 3 行缓存方案：在 Sobel 核计算前对 9 个抽头取中值）；
3. 把 `MEDIAN` 参数接到实例的 enable（或 `generate if (MEDIAN)`），默认 0；
4. 构建（`_build_rtl.ps1`），检查：4 步 exit=0、RAM10 ≤256、时序 0 违例；
5. 上板对比：椒盐噪声/暗部颗粒应减少，边缘位置不偏移（用棋盘/文字特写对照）；
6. 把新 bit 存档到 `_bitbk/`，并更新两套交付 bit（若中值版验收通过）。

## 7. 2026-10-21 实际整合（已完成构建，待上板确认）

**同学交付物**（`G:\资料\2026嵌入式FPGA赛\中值滤波\降噪\降噪\`）：
- `median3x3.v`：**纯组合** 3×3 中值，19 个比较器，9 个窗口抽头输入，**0 块 RAM10**，约 120–160 LUT；无 clk/rst（可选 REG_OUT）。
- `camera_hdmi.v`（基于旧版 320 源码）+ 4 个参数：`MEDIAN`、`DN_AVG`（2×2 四点平均）、`DN_FUSE`（中值+平均融合）、`DN_TEMP`（灰度帧间 IIR）。
- 4 个候选 bit（0 对照 / 1 平均 / 2 平均+中值 / 3 最强），文档明确**尚未上板**；其结论：灰度噪声主因是 2×2 点采样 + 最近邻放大 + 灰度 IIR 被 `COLOR` 门控关死，中值只治椒盐。

**我们的整合**（320 左右分屏基础版，`02_源码_320左右分屏/`）：
- 复用 Sobel 3×3 窗口的 9 个抽头（`r2_t2..gd1`），**零新增行缓存、零新增拍延迟、0 块 RAM10**；
- 参数：`MEDIAN=1, DN_AVG=1, DN_FUSE=1, DN_TEMP=0`；
- `camera_hdmi.xml` 增加 `median3x3.v`；`_build_rtl.ps1` 同步列表已加 `median3x3.v`；
- 新 bit：`03_bit/camera_hdmi_split_lr_median.bit`（1,887,426 B）；
- 构建：RAM10 **83/256**、最小 slack **+0.005 ns**、**0 违例**、0 error。

**关键说明（重要）**：
- 同学的接法是把中值结果替换**显示/写帧缓存的中心像素 `gd2`**；Sobel 的 8 个邻域抽头不变（Sobel 中心系数为 0）→ **边缘图本身不受中值影响**，降噪体现在左半灰度显示。
- 若要让**高阶版红边**也吃到中值，需要做“真·前置中值”：在灰度流进入 Sobel 前插 2 行缓存，并把写地址/行计数延迟 2 行（+2 块 RAM10、2 行对齐风险），本轮未做。
- `DN_TEMP`（灰度 IIR）在 SPLIT 下 `blend_gray=0` 不生效，且 +76 块 RAM10，故关闭；非分屏灰度档可另行评估。

**待办**：用户上板对比左半灰度（椒盐/暗部麻点是否减少、是否变糊）；若 OK，把该版作为基础版交付 bit；再做“真·前置中值”用于高阶红边（可选）。

- 若同学交付的模块延迟不是 2 行+1 像素，请把实际延迟写进本文件，并相应调整顶层 `cap_y`/`pcol` 延迟。
