## 1. 一页纸

- **数据流**：OV5640（DVP 8bit，RGB565）→ 灰度 `Y8=(77R+150G+29B)>>8` → 3×3 Sobel（`G=|Gx|+|Gy|`）+ 双阈值迟滞（48/64）→ 帧缓存 → 读回 → HDMI **640×480@60Hz**
- **帧缓存**：板载 DDR3（K4B4G1646E，4Gbit×16）；4 块 × 4MB buffer、读写不撞块、无撕裂
- **帧率**：相机 **30.00fps**（VTS=1688）、显示 60.00Hz、严格 **2:1（hold=2）**，无抽动
- **两套 bitstream**：
  - **高阶版**：640×480 **全分辨率** RGB332 彩色 + 纯红边缘（EDGE_COLOR=1）
  - **基础版**：320×240 存储 + 2× 放大，**左右分屏**（左原始灰度 / 右 Sobel 边缘）
- **时序/资源**：0 违例；RAM10 91/256（高阶）、83/256（基础）
- **诊断**：UART 115200 软显示器（64×48 缩略图 + 帧率/帧周期遥测）、6 颗 LED 关卡条

## 3.2 高阶增强版（2026-11-02，待上板）

`03_bit/camera_hdmi_enhanced_320.bit`（1,966,683 B）

- 基线：320 左右分屏 + 中值 + Canny（严格版）；
- 新增 **实时阈值**（高阶 #2）：K1/K2 按键消抖 + 步进 + 连发，阈值同时作用于 Sobel 与 Canny；
- 新增 **简易目标识别**（高阶 #6）：帧级 bbox + 边框重合度，判圆/矩形，白框 + 左上角 16×16 状态块（空心=圆，实心=矩形）；
- 资源：RAM10 **87/256**（两模块 0 RAM10）、min slack **+0.026 ns**、**0 违例**；
- 模块：`00_公共RTL/thr_ctrl.v`、`00_公共RTL/shape_detect.v`（C 交付，A 修复：`edge` 是 Verilog 关键字 → `edge_i`；x/y 改顶层 `pcol/row_d1` 直输；tb 改 negedge 驱动消除竞争）；
- 引脚（已从 `camera_hdmi.pinout.rpt` 核对）：**K1=GPIOL_P_07 / key_plus**、**K2=GPIOL_N_06 / key_minus**（1A、1.8V、weak pullup）；\n- 板测：K1 连按 3 下边缘变少、K2 变多；白纸画圆/方块，出现白框 + 状态块（空心圆/实心方）；移开消失。

## 3.3 全分辨率增强版（2026-11-02，推荐主推，待上板）

`03_bit/camera_hdmi_fullres_enhanced.bit`（1,937,550 B）

- **640×480 全分辨率彩色 + 红边**（早期 B1 基线）+ **实时阈值（K1/K2）** + **简易目标识别（圆/矩形）**；
- **阈值上电默认 = 早期固定值 48/64**：K1 阈值加、K2 阈值减；
  - 修复：板上 rst_n=KEY0 按键，上电未按时不会走复位分支，FPGA 寄存器初值 0 → 旧版 thr_ctrl 输出 0/0，边缘爆炸；现在未按键前直接输出 INIT_LO/INIT_HI（48/64），第一次按键从 48/64 开始加减 —— 初始画面与早期不带 K1 的版本一致；
- **识别改为“暗区填充率”法**（不再用边缘覆盖率/bbox）：
  - 黑形状 = 灰度 < 80；统计 ROI（中心 240×180）内暗像素的 bbox/个数；
  - 填充率 = 暗像素数 / bbox 面积：矩形 ≈0.9~1.0 → **实心块**；圆 ≈0.6~0.9（π/4≈0.785）→ **空心块**；
  - 长宽比 0.7~1.43；暗像素太少/框太小 → 不显示；
  - 资源：0 RAM10；演示需**白底 + 黑形状居中占满 ROI**；
- 黑框 + 目标框左上角状态块：空心=圆、实心=矩形。

## 3.4 全分辨率左右分屏（2026-11-02，基础 #4，无马赛克）

`03_bit/camera_hdmi_splitview_fullres.bit`（1,900,368 B）

- **640×480 1:1 显示**：左半屏 = 边缘图（全分辨率 Canny 红边像素 -> 白线/黑底），右半屏 = 灰度（RGB332 亮度）；
- 不再经过 320×240 -> 2× 放大，所以没有 2×2 马赛克，边缘是 1 像素细线；
- 左/右按显示 x 分界（左 320 列边缘、右 320 列灰度），DDR 顺序读不变、无新增帧缓存；
- K1/K2 仍可调 Canny/Sobel 阈值；识别框在分屏模式下不叠加（分屏是基础 #4 演示，识别看 v6）；
- 构建参数：`camera_hdmi.v` 里 `SPLITVIEW=1` 构建本 bit，`SPLITVIEW=0` 构建 v6 彩色叠加 bit。

## 5. 构建（可选；直接用 03_bit 里的 bit 更省事）

1. 把某个源码目录的 6 件套 + ROM 放进 Efinity 工程目录（如 `E:\efinity_project\104.2\`）；

## 6. 烧录

1. 接好：电源、FTDI 下载器 USB、CH340 串口 Mini-USB、HDMI、OV5640（反插）；

## 7. 验证

### 7.1 串口（推荐）

- 115200-8-N-1；帧头格式：
  ```
  '@' + 帧号(2hex) + 状态字(2hex)
      + 相机帧周期(8hex) + 行周期(6hex) + 显示帧周期(6hex) + hold(2hex) + CRLF
  单位均为 clk_sys = 96MHz 拍
  ```
- 期望值：
  - 状态字 **`FF`**（bit0 hdmi_pll / bit1 ddr_pll / bit2 cal_done / bit3 cal_pass / bit4 cfg_done / bit5 DVP / bit6 any_ack / bit7 版本标记）
  - 相机帧周期 **`0030D5C0`** = 3,200,448 拍 = **30.00fps**
  - 显示帧周期 **`0186A00`** = 1,600,000 拍 = **60.00Hz**
  - hold = **`02`**（严格 2:1）
- 无 HDMI 时可用 `06_工具/uart_view.py` / `_probe_tp.py` 把 64×48 缩略图画成 PNG。

## 8. 已知问题 / 说明

1. **P1 亮度回摆**：AEC 仍开，缩略图均值有 ±5 的缓慢回摆；手动曝光/增益尝试失败（`0x3509` 写 `0xD0` 反而更暗，增益寄存器映射需查 OV5640 数据手册）。不影响功能与帧率。
2. **基础分屏版分辨率**：320×240 存储 + 2× 放大，左半屏（灰度）分辨率略低于高阶版；高阶版是 640×480 全分辨率。
3. **全分辨率左右分屏未采用**：构建后 DDR 控制器内部 `core_clk → twd_clk` 路径出现 **-0.015 ns** 违例（官方 IP 内部路径，PnR 变化导致），为守住“时序 0 违例”未采用。
4. **时域 IIR 关闭**：全分辨率下 `u_hist` 需要 300 块 RAM10（装不下），已条件化关闭；降噪由 3×3 中值滤波（已集成在基础版）补。
5. **中值滤波已集成（高阶挑战 1）**：包内 `00_公共RTL/median3x3.v` 与 `02_源码_320左右分屏/median3x3.v` 均在；基础版 bit 已上板。
